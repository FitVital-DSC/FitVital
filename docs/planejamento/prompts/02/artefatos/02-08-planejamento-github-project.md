# Artefato 8 — Planejamento do GitHub Project

## Configuração

O campo **Status** deve conter exatamente:

1. `Backlog`
2. `Ready`
3. `In Progress`
4. `In Review`
5. `Done`

Não utilizar `Todo`, `No Status` ou estados adicionais.

## Distribuição inicial

| Item | Status inicial | Justificativa |
|---|---|---|
| Epic `[UC02] Realizar Check-in (Controle de Acesso)` | Ready | Escopo e critérios estão documentados |
| SUB-01 | Ready | Unidade inicial, sem dependências |
| SUB-02 | Backlog | Aguarda refinamento do modelo |
| SUB-03 | Backlog | Aguarda domínio e contratos |
| SUB-04 | Backlog | Aguarda serviço e contratos |
| SUB-05 | Backlog | Aguarda contrato da catraca e serviço |
| SUB-06 | Backlog | Aguarda operação de ocupação e decisão de concorrência |
| SUB-07 | Backlog | Aguarda componentes e decisões |
| SUB-08 | Backlog | Consolida as evidências |

## Definition of Ready

Objetivo, escopo, origem documental, critérios testáveis, dependências e responsável devem estar definidos. Protocolos ou decisões ausentes devem estar explicitamente registrados como pendências antes da movimentação para `Ready`.
